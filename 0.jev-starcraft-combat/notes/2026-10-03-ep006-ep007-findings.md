# Episodes 006 and 007: run results and findings

Date: 2026-10-03. Runs by Claude Code on the author's machine (Windows 11, StarCraft II on Low,
`typesafe-sdk` 0.7.2, Jev `jev-1.13.0`). Code lives on the PR branches, not on `main`:

- 006: PR #1, branch `ep006-semantic-net`, folder `0.jev-starcraft-combat/006-sc2-semantic-net/`
- 007: PR #2, branch `ep007-trainable-semantic-policy` (stacked on 006), folder
  `0.jev-starcraft-combat/007-sc2-trainable-semantic-policy/`

Scenario for both (inherited from 005): 12 Marines vs 10 Banelings + 10 Zerglings, paused
evaluation (`realtime=False`), decisions every 12 game loops (0.54 s), 60 s fight cap.
Score = Zerg killed if at least one Marine survives, else 0.

## TL;DR

- **006 (Jev semantic net):** 16/20 wins. Worse than the 005 commander (20/20) and than
  scripted `stutter_all` with no AI (20/20). The six perceptions vary meaningfully, but removing
  the commander also removed the pre-contact split and the focus-fire target.
- **007 (trainable MLP over frozen Jev perception):** the PR trainer barely moved the weights.
  After a fix, 40 training fights still showed no learning (12/20 then 13/20 wins), and the
  argmax policy of every checkpoint collapses to `bait`. Episodic REINFORCE with one terminal
  reward per fight is too weak a signal at this scale. Recommended next step: behavior cloning
  from logged 005/006 decisions, then fine-tune, and evaluate by sampling, not argmax.
- Jev as a pure perception layer works: one batched call with 6 global + 4 x 12 local Noul
  questions has a median latency of 148 ms (p90 190 ms), about 170k input tokens per fight
  (~$0.007).

## Episode 007: trainable semantic policy

### Original PR code (4 training fights, seeds 1000-1003)

3 wins, 1 loss. The plumbing works (batched perception call, weights saved after each fight).
But learning was effectively off:

1. **Step size.** `lr=0.003` divided by the number of Marine-steps per fight (~300-600). After 4
   fights the weights had moved 0.03% and the action probabilities were unchanged (each ~10-13%).
2. **Advantage.** `clip((reward-15)/5, -1, 1)`: every win (~21-26) maps to +1 and every loss to
   -1. The survival and HP terms are clipped away, so a clean win and a scrappy win get the same
   update.
3. **Credit for actions that never ran.** The trajectory stores the sampled action, but 005's code
   reflexes (kite near a Baneling, regroup) often replace it. Sampled mix was near uniform;
   executed mix was 20% kite.
4. **Wins come from the code, not the net.** The 005 reflexes and stutter default keep a
   near-random net winning about 3 of 4.

### Fix applied (`8e3908c`, plus logging in `b15c3e1`)

- `learning_rate` 0.05 (still averaged over kept steps).
- Advantage = (reward - EMA baseline) / EMA std, clipped to +-3. The first episode only sets the
  baseline. Baseline, variance and episode count persist in the weights JSON.
- `bot._apply_plan` calls `policy.observe_executed(executed)`; steps whose sampled action was
  replaced by code rules are dropped from the trajectory.
- `summary.json` logs `training_advantage`; `decisions.jsonl` logs per-Marine
  `local_activations`.
- Stale policy-name tests updated. 195 tests pass.

### Training run after the fix (seeds 1000-1039, `--train`, one weights file)

| Block | Wins | Marines alive | Zerg killed |
|---|---|---|---|
| fights 1-20 | 12/20 | 2.7 | 18.3 |
| fights 21-40 | 13/20 | 2.1 | 18.6 |

Advantages behave as intended (wins about +0.6 to +0.9, losses about -1.1 to -3.0 once the
baseline settled near 14.5, std near 10.9). No learning trend.

What the net learned, probed on 4,765 real (global, local) activation vectors from the training
logs:

| Checkpoint | Weight change (rel. W1) | Mean action probability range | argmax share |
|---|---|---|---|
| ckpt-000 (init) | 0 | 0.09-0.13 | bait 63%, split 31%, stim 6% |
| ckpt-020 | 2.1% | 0.08-0.14 | bait 91%, split 9% |
| ckpt-040 | 2.0% | 0.08-0.14 | bait 83%, split 17% |

The policy is still near uniform. Frozen argmax evaluation would mostly measure "every Marine
baits" (the largest of nine nearly equal logits), so the planned per-checkpoint evaluation runs
were skipped. Checkpoints are in `007-sc2-trainable-semantic-policy/models/`.

Cost and latency: 6,846,602 input tokens over 40 fights ($0.29). Perception call median 147.7 ms,
p90 190.0 ms, inside the 535.7 ms budget.

### Why it does not learn, and what to try

One terminal reward is shared by ~300 Marine decisions per fight. The per-step gradients point in
different directions and mostly cancel, so the expected update per fight is tiny compared to the
noise. Plain REINFORCE would likely need hundreds to thousands of fights (~40 s each, ~$0.007
each).

Options, in recommended order:

1. **Behavior cloning first.** Train the same 10 -> 16 -> 9 net to imitate logged executed actions
   (005 commander, 006 semantic net; 007 now logs the matching local activations). Seconds of
   compute, no new fights. Then fine-tune with the fixed trainer. Evaluate by sampling from the
   softmax (or a temperature), not argmax.
2. **Per-step credit.** A shaped reward per decision window, e.g. Zerg killed minus Marines lost
   in the next 2 s, attributed to the Marines involved. Stronger signal, but it is a reward-design
   choice.
3. **Brute force.** 200-500 more fights with the current trainer.

Separately: the 005 reflexes and stutter default sit between the net and the game. They keep a
random net winning ~60%, which hides what the net itself does. A cleaner 007 run would log or
reduce those overrides.
